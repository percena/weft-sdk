# online-store — the Weft skill-integration reference apps

Two variants of the same store — the `integrate-weft-kit` skill's scaffold source
(`classic/`) + its skill-built output (`agentic/`, which is also the reference the
skill copies the browser layer from).

## Directory structure

| Dir | What it is | How it was generated |
|---|---|---|
| `classic/` | A traditional REST store (no AI) — the scaffold source. | Hand-written (a realistic e-commerce REST API + SPA). The **input** to the skill — not generated by it. |
| `agentic/` | The same store + a Weft chat agent that drives it. | **Generated by the `integrate-weft-kit` skill** from `classic/` (copy + overlay the weft layer + wire + provision). |

## `classic/` — the traditional store

A realistic small e-commerce REST API + SPA, no AI. **6-product catalog**
(⌨️ keyboard, 🖱️ mouse, 🎧 headphones, ⌚ watch, 🖥️ monitor, 🔊 speaker),
**per-customer carts** (cookie-session-scoped), **orders with a state machine**,
an **SSE event feed**, **cookie auth**, and a polished storefront UI (product
grid, cart with qty management, order list with a status timeline).

**State machine** (the reactive backstop) — 8 states × 8 actions:

```
pending_payment → paid → shipped → delivered → completed
                 ↘ cancelled (from pending_payment | paid)
refund_requested → refunded | deny_refund → $prior (restore)
```

Illegal transitions return `409 { error, allowed_actions }`. `deny_refund`
restores the prior status (`$prior` back-edge); `cancel` / `approve_refund`
restock.

**REST API — 25 endpoints:**
- **Utility (6):** `POST /api/login`, `POST /api/logout`, `GET /api/me`,
  `GET /api/events` (SSE), `GET /api/state` (snapshot), `POST /api/reset`.
- **Business (19):** products `list` / `get` / `update`; cart `get` / `clear` /
  `add` / `update` / `remove`; orders `create` / `list` / `get` + `pay` /
  `cancel` / `ship` / `deliver` / `confirm` + refund `request` / `approve` /
  `deny`.

Of the 19 business endpoints, **15 are exposed to the agent as tools** (the
OpenAPI spec — the skill derives `tool_names` from it). The other 4
(`getProduct`, `updateProduct`, `updateCartItem`, `removeCartItem`) are REST-only
— the agent doesn't need them: it `listProducts` to match names, and qty changes
go through `addCartItem`.

**Complexity assessment:** 15 agent tools, an 8-state SM with refund `$prior`, a
cross-session reference regression (the "shop bug" — operating on a pre-existing
order id), a fail-open dependency graph (15 nodes / 18 edges). Enough to exercise
every skill feature; small enough to reason about end-to-end.

### Build + use

```sh
cd apps/online-store/classic
pnpm install
pnpm test     # 13/13 — the SM + REST route tests
pnpm start    # builds the web bundle + serves on http://127.0.0.1:19743
```

Open the URL, log in (any username), and use the storefront — browse, cart,
checkout, drive an order through its lifecycle. No weftd, no AI, no `.env` creds.

## `agentic/` — how it came to be

`agentic/` is **built by the `integrate-weft-kit` skill** from `classic/`. The
skill's runbook (`skills/integrate-weft-kit/SKILL.md`) drives the pipeline. Here's
what it did + how manual each step was.

### The pipeline (classic → agentic)

1. **Scaffold** — copy `classic/` → `agentic/` + the deltas: `package.json`
   (name + `@percena/weft` dep), `vite.config.ts` (port 19745), `tsconfig.json`
   (`types:["vite/client"]`), `index.html` (title). **Automated** — one copy + sed.
2. **Overlay the weft layer** — copy the skill's `templates/` (`provision.mjs`,
   `session-routes.mjs`, `run.mjs`, `.env.example`, `ChatPane.tsx`,
   `chat-bootstrap.ts`, `auth-context.tsx`, `customer.ts`) + the browser shell
   (`App.tsx`, `ShopPanel.tsx`, `main.tsx`, `shop-api.ts`, `index.css`,
   `i18n-init.ts`) + `lib/` (`system-prompt.mjs`, `proc.mjs`) +
   `scripts/gen-shop-graph.ts`. Substitute the `{{port}}` / `{{appSlug}}` /
   `{{toolset}}` / … placeholders. **Automated** — copy + a `{{\w+}}` regex
   substitute.
3. **Wire `shop-server.mjs`** — add `import { createProvisioning } from
   './provision.mjs'` + `import { wireSessionRoutes } from './session-routes.mjs'`
   + `import { buildShopSystemPrompt } from '../lib/system-prompt.mjs'`; resolve
   creds from env; call `createProvisioning(...)` + `wireSessionRoutes(server,
   {...})` (it **wraps the request listener** — CORS/OPTIONS + `/api/chat/*` +
   the `/v1` reverse proxy, falling through to the REST routes); return
   `ensureApp`. **Runbook-driven** — one wiring edit (the LLM integrator does it
   per the runbook; the only hand-written code in the pipeline, but
   `wireSessionRoutes` wraps the listener, so no REST-route surgery).
4. **Derive `tool_names`** — `<toolset>_<operationId>.toLowerCase()` for every
   operationId in the OpenAPI (15 names). **Automated** — the provisioning chain
   derives them inline from the spec.
5. **Generate + review the dependency graph** — `weft-api-graph` (shipped inside `@percena/weft`) produces the DAG
   (all edges `required:false` — fail-open); the integrator reviews each edge
   (produce vs reference) + sets `verified:true`. **Automated** — generation is
   automatic (fail-open default, all `required:false`). The per-edge review
   (promote to `required:true` / `verified:true`) is an **optional** safety
   hardening — the site works correctly on the unreviewed fail-open graph.
6. **State machine** — `shared/meta.mjs` is already in `classic/` (the SM is
   shared, unchanged). The system-prompt (`lib/system-prompt.mjs`) renders it at
   runtime so the prompt can't drift. **Automated** — no change.
7. **Provision on weftd** — `node run.mjs` builds the web bundle, asserts the
   weftd creds (`assertWeftdCreds` fail-fast), starts the server, +
   `ensureApp()` lazily provisions the app + toolset + skill + automation + graph
   on the weftd tenant (background warm-up). **Automated**.
8. **E2e (Phase 3)** — a **headed** Playwright run: log in → set permission
   `Auto` → "buy 2 mechanical keyboards and pay" → watch the agent drive the
   `shop_*` tools + the action-bridge automated live cursor replay on the storefront →
   verify via `GET /api/state`. **Optional** — the site is up + serving before the e2e; the e2e verifies (self-repair loop on failure). Recommended, not required.

### What was modified (classic → agentic)

- **`package.json`** — added `@percena/weft`, `i18next`,
  `react-i18next` (the weft SDK — which also bundles the `weft-api-graph` analyzer/bin — + i18n).
- **`server/`** — added `provision.mjs` (the weftd provisioning chain) +
  `session-routes.mjs` (the chat-session backend + the **verbatim** `/v1` reverse
  proxy — production-hardened TLS retry); `shop-server.mjs` wired (3 imports + the
  `createProvisioning` / `wireSessionRoutes` calls + `ensureApp` in the return).
- **`src/`** — `ShopPanel.tsx` now has the **action-bridge** (`ActionReplayLayer`
  + `weftAction` — the automated-live-cursor that visually replays the agent's tool calls);
  `App.tsx` has the chat sidebar + bootstrap-retry; `main.tsx` loads i18n + the
  weft styles; + `ChatPane.tsx`, `chat-bootstrap.ts`, `i18n-init.ts`.
- **`lib/`** — `system-prompt.mjs` (renders the SM into the agent prompt) +
  `proc.mjs` (`.env` loader).
- **`scripts/gen-shop-graph.ts`** — generates + reviews the dependency graph.
- **`run.mjs`** — `assertWeftdCreds()` fail-fast + `ensureApp()` warm-up.
- **`online-store-agentic-graph.json`** — the reviewed DAG (15 nodes, 18 edges,
  all `required:false` + `verified:true`).
- **`.env`** — weftd creds (`WEFTD_BASE`, `WEFT_API_KEY`, `WEFT_TENANT_ID`,
  `OPENAI_*`).

The `classic/`'s REST routes, state machine (`shared/meta.mjs`), + storefront
logic are **unchanged** — the weft layer is added on top, not mixed in.

### Fully automatable — human review is optional, not required

**The pipeline is fully automatable** — the `integrate-weft-kit` skill can produce
a working agentic site end-to-end, **no human intervention required to close the
loop**. The skill's runbook drives every step, and the defaults are chosen so the
result works out-of-the-box:

- The **dependency graph** generates **fail-open** (all edges `required:false`) —
  the agent operates every tool without any per-edge review. The review (promoting
  edges to `required:true` + `verified:true`) is a **safety hardening + routing
  optimization**, not a prerequisite — the site runs correctly on the unreviewed
  fail-open graph.
- The **execution model** is auto-decidable from the reachability + auth model
  (same-origin + cookie + local → `client`; see `references/execution-model.md`).
- The **state machine** is shared (`meta.mjs` — the same module the backend
  uses), so the system-prompt can't drift.
- The **e2e** is a **verification** (does the agent actually drive the tools
  correctly?), not a build step — the site is up + serving before the e2e runs.

**We recommend developers review the AI's output** (the graph edges, the
state-machine, the e2e) — best-practice due-diligence on a generated artifact,
the same way you'd review a PR. But it's **icing on the cake**: the
skill's defaults produce a correct, running agentic site without it.

**This is the key UX differentiator.** Other "AI-assisted integration" tools
can't close the loop without a human in the middle — they generate fragments a
developer must assemble, wire, + debug. The `integrate-weft-kit` skill closes the
loop **fully automated**: from a traditional REST app to a running agentic site,
end-to-end. The human review is an optional quality gate, not a dependency.

**The normal pipeline shape** (fully automated; the review gates are optional):

```
scaffold (copy classic + deltas)
  → overlay templates (substitute {{placeholders}})
  → wire shop-server (one runbook-driven edit)
  → derive tool_names (from the openapi)
  → gen graph (fail-open, all required:false)  →  [optional] review per-edge
  → state machine (shared, no change)
  → system-prompt (rendered from the SM at runtime)
  → decide execution (auto: same-origin+cookie+local → client)  →  [optional] confirm
  → provision on weftd (run.mjs, background warm-up)
  → site is up + serving  →  [optional] e2e (headed Playwright) to verify
```

A full build from `classic/` to a running agentic site is ~10 min (mostly the
provisioning + the web build). The skill's two reproducible generations (gen 1
+ gen 2) produced **byte-identical source** (only the graph's `generated_at`
timestamp differed) — the pipeline is deterministic.

### Build + use

```sh
cd apps/online-store/agentic
cp .env.example .env   # fill WEFTD_BASE / WEFT_API_KEY / WEFT_TENANT_ID / OPENAI_*
pnpm install
pnpm test     # 13/13 — same SM + REST tests as classic
pnpm start    # builds the web bundle + starts on 19745 + provisions on weftd
```

Open `http://127.0.0.1:19745`, log in, set the chat permission mode to `Auto`,
and tell the agent e.g. "buy 2 mechanical keyboards and pay" — it drives the
store's REST API through the named `shop_*` tools, the action-bridge automated live cursor
replays each tool call on the storefront, and the order lands in `/api/state`.

## The skill

`skills/integrate-weft-kit/` — the lean runbook (`SKILL.md`) + parameterized
`templates/` (the agentic layer) + `references/` (the fail-open / `plan_route` /
execution-model theory). It turns a traditional REST app (`classic/`) into an
agentic app (`agentic/`) by the pipeline above. **Zero custom generator scripts**
— the runbook drives the `weft-api-graph` bin (shipped inside `@percena/weft`) + the runtime
`lib/system-prompt.mjs`. See `SKILL.md` for the full runbook + Phase 3 (e2e +
self-repair) + Phase 4 (hand-off for developer review).
